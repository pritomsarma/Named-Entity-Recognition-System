01 — introduction

Turning raw broadcast transcripts into structured facts

Problem statement

Broadcast and news text is dense with names, organisations, places and dates, but it arrives as an unstructured stream of words. Dictionary and regex-based lookups fail the moment a spelling variant, a new organisation, or an unfamiliar name appears — and they can't tell "Washington" the city from "Washington" the person. Any downstream use of the text requires reliable entity extraction.

Solution description

This project fine-tunes a pretrained BERT encoder for token-level Named Entity Recognition, framed as BIO-tagged sequence labelling over four classes — PER, ORG, LOC and MISC. An optional CRF layer enforces valid tag transitions, protected by a two-phase discriminative fine-tuning strategy. Ships as a full CLI and an interactive Streamlit dashboard.

The project's working title targeted a DATE category; in practice the CoNLL-2003 schema it trains on folds dates, events, nationalities and other named entities into a broader MISC class, which is what every score on this page reports against.

Setup & installation

Python 3.9+, pip, and — optionally — a CUDA-capable GPU for faster training.

01

Clone the repository

# git clone https://github.com/pritomsarma/Named-Entity-Recognition-System.git
cd Named-Entity-Recognition-System

Create a virtual environment

python -m venv .venv
# Windows
.venv\Scripts\activate
# macOS / Linux
source .venv/bin/activate
03

Install dependencies

pip install -r requirements.txt

Core stack: PyTorch 2.0+, 🤗 Transformers 4.30+, pytorch-crf, seqeval, and Streamlit 1.30+.

04

Train model

# quick run — CoNLL-2003 subset, 4 epochs
python train.py

# recommended — two-phase discriminative fine-tuning
python train.py --fine_tune --freeze_epochs 2 --epochs 6

# full CoNLL-2003 (~14k examples)
python train.py --full_data --epochs 10 --fine_tune

Predict & evaluate

python predict.py --demo
python predict.py --model_path checkpoints/best_model.pt --text "Anderson Cooper reported from New York on CNN."
python eval_test.py   # precision / recall / F1 via seqeval

Launch the dashboard

streamlit run app.py

03 — architecture

From raw text to labelled spans

Every stage the input passes through, in order — tokenisation, encoding, regularisation, classification, and decoding.

1

Sub-word tokenisation

The BERT WordPiece tokenizer splits raw text into sub-word tokens and IDs so out-of-vocabulary names receive sensible representations.

BertTokenizerFast · max_seq_length = 128
2

BERT encoder

Token IDs pass through bert-base-uncased, producing a 768-dimensional contextual embedding per token.

hidden_size = 768
3

Dropout regularisation

A dropout mask regularises encoder outputs before classification to prevent overfitting on smaller fine-tuning splits.

dropout_rate = 0.3
4

Linear classifier

A linear layer projects each regularized token embedding onto per-token logits across the 9 BIO tag classes.

num_labels = 9 (O, B-/I- × PER, ORG, LOC, MISC)
5

CRF Decoding

Config determines how logits map to sequences.

Yes → CRF (Viterbi) decoding — enforces valid transitions
No → per-token argmax decoding
6

BIO tags → entities

Consecutive B-/I- tags of identical types are merged back into clean entity spans complete with confidence metrics.

04 — mathematics

The equations behind key pipeline decisions

Structured decoding — CRF sequence score

The CRF layer scores full tag paths instead of isolated tokens, combining emission matrices with a learned transition matrix:

s(x, y) = \sum_{t=1}^{T} E_{t, y_t} \; + \; \sum_{t=1}^{T-1} A_{y_t, y_{t+1}}

Viterbi decoding searches \hat{y} = \arg\max_y s(x,y) to forbid illegal transitions like O → I-PER.

Label smoothing loss

Cross-entropy is softened to protect the classifier from overconfidence when training on smaller subsets:

\mathcal{L} = -(1-\epsilon)\log p_{y} \; - \; \frac{\epsilon}{K}\sum_{k=1}^{K} \log p_k

Using parameter settings \epsilon = 0.1 and K = 9 classes.

Discriminative learning rates

Phase 1 trains only the classifier head; Phase 2 unfreezes BERT at a lower rate to prevent catastrophic forgetting:

\eta_{\text{encoder}} = \begin{cases} 0 & \text{Phase 1} \\ 2\times10^{-5} & \text{Phase 2} \end{cases} \quad \eta_{\text{classifier}} = 5\times10^{-4}

Linear warmup & decay schedule

\eta(t) = \begin{cases} \eta_{\max} \cdot \frac{t}{t_{\text{warmup}}}, & t \le t_{\text{warmup}} \\ \eta_{\max} \cdot \frac{T-t}{T - t_{\text{warmup}}}, & t > t_{\text{warmup}} \end{cases}

Ramps up over the first 10% of optimizer steps to stabilize initial head weights.

08 — engineering

Engineering decisions behind the numbers

Two-phase unfreezing rationale

Phase 1 warms up the fresh classifier head for 2 epochs. Unfreezing the encoder in Phase 2 at a 25× lower learning rate triggers an immediate performance jump as the classifier leverages properly adapted contextual features.

01 — introduction

Turning raw broadcast transcripts into structured facts

Problem statement

Broadcast and news text is dense with names, organisations, places and dates, but it arrives as an unstructured stream of words. Dictionary and regex-based lookups fail the moment a spelling variant, a new organisation, or an unfamiliar name appears — and they can't tell "Washington" the city from "Washington" the person. Any downstream use of the text — indexing, search, fact-checking, analytics — first needs those entities pulled out and labelled reliably.

Solution description

This project fine-tunes a pretrained BERT encoder for token-level Named Entity Recognition, framed as BIO-tagged sequence labelling over four entity types — PER, ORG, LOC and MISC. An optional CRF layer sits on top of the linear classifier to enforce valid tag transitions, and a two-phase discriminative fine-tuning strategy protects BERT's pretrained language knowledge while the classifier head learns. The result ships as a CLI (train / predict / evaluate) and an interactive Streamlit dashboard.

The project's working title targeted a DATE category; in practice the CoNLL-2003 schema it trains on folds dates, events, nationalities and other named entities into a broader MISC class, which is what every score on this page reports against.

02 — setup

Setup & installation

Python 3.9+, pip, and — optionally — a CUDA-capable GPU for faster training.

1

Clone the repository

# git clone https://github.com/pritomsarma/Named-Entity-Recognition-System.git
cd Named-Entity-Recognition-System
2

Create a virtual environment

python -m venv .venv
# Windows
.venv\Scripts\activate
# macOS / Linux
source .venv/bin/activate
3

Install dependencies

pip install -r requirements.txt

Core stack: PyTorch 2.0+, 🤗 Transformers 4.30+, pytorch-crf, seqeval for entity-level metrics, and Streamlit 1.30+ for the dashboard.

4

Train

# quick run — CoNLL-2003 subset, 4 epochs
python train.py

# recommended — two-phase discriminative fine-tuning
python train.py --fine_tune --freeze_epochs 2 --epochs 6

# full CoNLL-2003 (~14k examples) — several hours on CPU
python train.py --full_data --epochs 10 --fine_tune
5

Predict & evaluate

python predict.py --demo
python predict.py --model_path checkpoints/best_model.pt --text "Anderson Cooper reported from New York on CNN."
python eval_test.py   # precision / recall / F1 via seqeval
6

Launch the dashboard

streamlit run app.py

Paste any text and click Analyze Entities to see colour-coded, confidence-scored entities highlighted inline.

03 — architecture

From raw text to labelled spans

Every stage the input passes through, in order — sub-word tokenisation, contextual encoding, regularisation, classification, and structured decoding.

1

Sub-word tokenisation

The BERT WordPiece tokenizer splits raw text into sub-word tokens and IDs, so out-of-vocabulary names still get sensible sub-token representations.

BertTokenizerFast · max_seq_length = 128
2

BERT encoder

Token IDs pass through bert-base-uncased, producing a 768-dimensional contextual embedding per token.

hidden_size = 768
3

Dropout

A dropout mask regularises the encoder output before classification — the main lever against overfitting on a small fine-tuning subset.

dropout_rate = 0.3
4

Linear classifier

A linear layer projects each regularised token embedding onto per-token logits over the 9 BIO tag classes.

num_labels = 9 (O, B-/I- × PER, ORG, LOC, MISC)
5

CRF enabled?

A config flag decides how the logits become a tag sequence.

Yes → CRF (Viterbi) decoding — enforces valid transitions
No → per-token argmax decoding
6

BIO tags → entities

Consecutive B-/I- tags of the same type are merged back into entity spans with text, label and confidence.

04 — mathematics

The equations behind the pipeline's key decisions

Structured decoding — CRF sequence score

The CRF layer scores an entire tag path rather than each token independently, forbidding illegal jumps such as O → I-PER.

s(x, y) = \sum_{t=1}^{T} E_{t, y_t} \; + \; \sum_{t=1}^{T-1} A_{y_t, y_{t+1}}

Label smoothing

The token-level cross-entropy loss is softened so the classifier head doesn't grow overconfident on a small subset:

\mathcal{L} = -(1-\epsilon)\log p_{y} - \frac{\epsilon}{K}\sum \log p_k

Discriminative learning rates

Phase 1 trains the head; Phase 2 unfreezes BERT at a lower rate — safeguarding against catastrophic forgetting.

\eta_{enc} \ll \eta_{class}

Dropout regularisation

Applied to the 768-dim BERT output before classification to prevent overfitting.

h' = h \odot m, \quad m_i \sim \text{Bernoulli}(1-p)

07 — engineering

Engineering decisions behind the numbers

Why unfreezing in two phases matters

Phase 1 (2 epochs, encoder frozen) warms up the fresh classifier head. The moment Phase 2 unfreezes the encoder — at a learning rate 25× lower than the classifier's — F1 jumps immediately to 0.918 in the very next epoch, because the classifier head now has a properly-adapted encoder underneath it instead of raw pretrained BERT features.

Watching for overfitting

Validation loss climbs steadily while validation F1 keeps inching up. That divergence is the model growing more confident on borderline predictions rather than getting them more often right — the exact pattern that label smoothing, weight decay and patience-based early stopping exist to catch before it turns into real regression.

One dataclass tree, not scattered constants

Configurations all bundle into a single NERConfig. Every script builds or loads the same config object, so a hyperparameter changed in one place can never silently drift between training and inference.

Small constraints that shaped the code

  • num_workers = 0 is forced on the DataLoader because Windows' multiprocessing model doesn't play well with a loaded BERT tokenizer across worker processes.
  • Full CoNLL-2003 training is CPU-bound in this setup.
